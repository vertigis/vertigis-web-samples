# CLAUDE.md

## Key Rules

-   Do not run a command unless the user asks for it. Example: do not build or test after a change.
-   Do not add a dependency unless the user asks for it.
-   Obey the rules in this file also when the existing code does not. The rules are always correct.
-   Write all messages in ASD-STE100 Simplified Technical English. You can use technical names and verbs from the code.
    Examples: `React`, `ESLint`, `yarn`, file names, and function names.

## The Repository

This repository is the VertiGIS Studio Web SDK Samples. It holds small sample libraries that show how to use the
VertiGIS Studio Web SDK. It also holds a viewer that shows each sample live at https://vertigis-web-samples.netlify.app.

-   It is a Yarn 4 monorepo. The only workspaces are `samples/*`. `viewer/` is not a workspace. `viewer/` holds a local preview of the live sample viewer.
-   Each directory in `samples/` is a Web SDK project (`@vertigis/web-sdk`). 

-   The samples are:
    - `arcade-editor`: Sample of an ESRI webcomponent running in Web.
    - `arcgis-widget`: Sample of an ESRI widget (old pattern) running in Web. 
    - `basic-component`: A basic Web component. 
    - `basic-service`: A basic Web service. 
    - `commands-and-operations`: Use of commands and operations in Web. 
    - `embedded-map`: Embedding a 3rd party map. 
    - `i18n`: Internationalizing Web components.
    - `icons-pack`: View the icons available in Web.
    - `iframe`: Run Web inside an iframe.
    - `tap-into-web-event`: Listen for an event in Web. 
    - `third-party-lib`: Integrate a 3rd party library with Web.
    - `ui-library`: Usage of the components in `@vertigis/web/ui`.

-   The structure of a sample:
    -   `src/index.ts` registers the components, models, services, commands, operations, and language resources with the
        `LibraryRegistry`.
    -   `src/components/<Name>/` holds `<Name>.tsx`, `<Name>Model.ts`, `index.ts`, and optionally `<Name>.css`.
    -   `src/services/<Name>/` holds `<Name>.ts` and `index.ts`.
    -   `app/app.json` and `app/layout.xml` are the configuration and layout of the sample app.
    -   `README.md` tells the user what the sample shows. The viewer shows this text below the sample.
    -   `sandbox.config.json` is the CodeSandbox configuration. CodeSandbox runs the `start-in-sandbox` script.

-   Each sample teaches one concept of the Web SDK. Samples should be small and focused on one concept.
-   `samples/library-viewer` is the sample viewer. It is also a Web SDK project. Its `app/app.json` lists the samples in
    the viewer. It imports `app/app.json`, `app/layout.xml`, `README.md`, and `build/main.js` of each sample with a
    relative path. Then it merges them into its own app at runtime. Thus the viewer needs the samples to be built first.
-   When a sample has `useHostPage: true` in `samples/library-viewer/app/app.json`, the viewer loads the sample in the
    `app/parent.html` page of the sample. Only the `iframe` sample does this.
-   The viewer shows links to the source on GitHub and to CodeSandbox for each sample. The links use the `master`
    branch.
-   `viewer/build/` is the Netlify output. Only `index.html`, `_headers`, and `_redirects` are source. Do not edit the
    other files.
-   The `build/` directories are build output. Git ignores them. Do not edit them.
-   `samples/icons-pack/src/_support/` is generated by `samples/icons-pack/pipeline/registerIcons.mts`. Git ignores it.
    Do not edit it.
-   `scripts/copy-static-files.js` copies the viewer and the samples in `samples/library-viewer/app/app.json` to
    `viewer/build` and is a prerequisite to running `yarn preview`. This script will be run automatically by `yarn build`.

## Commands

Run all commands from the root of the repository. The `yarn` version comes from Corepack.

-   `yarn`: install the dependencies.
-   `yarn build`: build all samples, then the viewer, then copy the output to `viewer/build`.
-   `yarn build:samples`: build all samples except `library-viewer`.
-   `yarn build:viewer`: build only `library-viewer`.
-   `yarn start`: start the viewer on port 3001. Run `yarn build:samples` first.
-   `yarn workspace <name> start`: start one sample on port 3001. `<name>` is the `name` in the `package.json` of the
    sample. Example: `yarn workspace sample-basic-component start`. The name of `commands-and-operations` is
    `sample-custom-commands-and-operations`.
-   `yarn test`: start the viewer and run the Cypress tests in Chrome. Run `yarn build:samples` first.
-   `yarn test:watch`: start the viewer and open the Cypress UI.
-   `yarn preview`: serve `viewer/build` on port 3012, as Netlify does. Run `yarn build` first.
-   `yarn prettier`: format all `.ts`, `.tsx`, `.js`, `.json`, and `.md` files.
-   `yarn audit`: audit the dependencies of all workspaces.
-   The pre-commit hook runs `prettier` on the staged files.

## Code Rules

-   Write TypeScript and React function components.
-   Import Web APIs from `@vertigis/web/*`. Import UI components from `@vertigis/web/ui/<Name>`. Import ArcGIS APIs from
    `@arcgis/core/*`. Import command argument types from `@vertigis/viewer-spec/*`. Do not import from MUI or
    `@vertigis/react-ui` directly.

-   The rules for writing code in Web also apply to these samples, eg:
    -   A model extends `ComponentModelBase` and has the `@serializable` decorator. Add each config property to the
        `<Name>ModelProperties` interface and to `_getSerializableProperties()`.
    -   A service extends `ServiceBase`. Register it with `registerService`. Register its commands and operations with
        `registerCommand` and `registerOperation` and the `serviceId` of the service.
    -   Use the `@command`, `@operation`, and `@canExecute` decorators from `@vertigis/web/messaging` to implement commands
        and operations.
    -   Use `useWatchAndRerender` to render a component again when a model property changes.
    -   The `namespace` in `registerComponent` must be the same as the `xmlns` of the custom prefix in `app/layout.xml`. Use
        `your.custom.namespace` in new samples.

-   Write comments that explain the Web SDK concept to the reader. The samples are teaching code.
-   In `README.md`, tell what the sample shows. Add links to the source files of the sample and to the
    [Developer Center](https://developers.vertigisstudio.com/docs/web/overview/).
-   Attempt to keep the versions of `@vertigis/web`, `@vertigis/web-sdk`, and `typescript` the same in all samples and in the root
    `package.json`.

-   If a sample has dependencies that would bring in a separate version of ESRI's JSAPI than used in the others, 
    add `"installConfig": { "hoistingLimits": "workspaces" }` to that sample's `package.json`. 
    -   This prevents the extra version of ESRI's JSAPI from affecting other samples and preventing builds from completing. 
    -   Note however that at runtime everything will be using the same version, so it still might not be compatible.

-   Obey `.prettierrc` and the `eslint.config.js` of each sample.

-   To add a sample:
    1. Copy a sample directory. Change the `name` in `package.json` to `sample-<directory>`.
    2. Add the directory name as an `id`, and a `title`, to the `libraries` list in
       `samples/library-viewer/app/app.json`.
    3. Add a Cypress test in `cypress/e2e/<directory>.cy.ts`.

-   Write PR titles in the Conventional Commits format. Example: `fix: update to latest Web SDK`. PRs go to `master`. This repo isn't versioned but do this anyway.
-   The samples themselves have versions that should be manually updated following semantic versioning if changes are made to the sample itself.

## Tests

-   The Cypress end-to-end tests are in `cypress/e2e/<name>.cy.ts`. `sample-viewer.cy.ts` tests the viewer.
    `arcade-editor`, `icons-pack`, and `tap-into-web-event` have no tests.
-   The tests open the viewer at `http://localhost:3001/#<sample>`. The sample is in an `iframe`. Many tests close the
    licensing alert first: `cy.getViewer().find('button[title="Close"]').click()`.
-   The custom commands are in `cypress/support/commands.js`, and their types are in `cypress/support/index.d.ts`.
    -   Use `cy.getViewer()` to get the sample.
    -   Use `cy.getViewer().getMap()` to get the map. The map helpers are in `cypress/mapUtils.ts`.
    -   For a sample with `useHostPage`, use `cy.getEmbeddedViewerHost()` to get the host page and
        `cy.getEmbeddedViewer()` to get the sample.
-   There are no unit tests.
-   CI (`.github/workflows/ci.yml`) runs `yarn`, `yarn build`, and `yarn test` for each push and PR to
    `master`. If the tests fail, CI saves the Cypress videos.
